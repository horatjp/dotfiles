# 取り込みメモ: abi/screenshot-to-code（本家、GitHub★7万超）

- 出典: https://github.com/abi/screenshot-to-code （`backend/prompts/` 配下のシステムプロンプト・ポリシー定義）
- 目的: スクリーンショット/Figma/画面録画をHTML・Tailwind・React・Vue等の動くコードに変換するAIプロダクト
- 注意: `screenshot-to-code-notes.md`（既存メモ）は別プロジェクト（onewave-ai/claude-skills の同名スキル）についてのもので、本メモとは無関係

## 転用した点

1. **参照画像の丸ごと埋め込み禁止 + 個別アセット抽出**: 元プロンプトは「画面全体を1枚の画像として貼るのは絶対禁止。ロゴ・写真等の個別アセットだけを抽出し、抽出できないもの（隠れている・背景の一部）は生成/プレースホルダーで代替する」と明言している。再現度を上げたいAIが「スクショをそのまま背景画像にする」という近道に流れやすいことへの対策 → `references/images.md` に反映（丸ごと埋め込み禁止・切り出しは矩形クロップに留める）
2. **複数参照画像の関係性判定**: 別ページ/別タブ・状態/無関係、の3パターンに分けてから作り始める、という分岐 → `SKILL.md` の「参照画像からの作成」に項目6として追加

## 教訓（裏付け・反面教師として）

- **必須の自己スクショ確認ループ**: 生成後に自分でヘッドレスブラウザでレンダリングし、参照画像と目視突合してから直す、という運用を"利用可能なら必ず実行"としている。これは本スキルの `references/screenshot-verify.md`（Step 4で必須試行）と同じ発想 — 新規性はないが妥当性の裏付けになる
- **反面教師: テキストのみ入力のデフォルトプロンプトが抽象語止まり**: 「モダンで洗練された見た目に」「プロフェッショナルな配色」「UXベストプラクティスに従う」という指示だけで具体的なデザイントークンや骨格の指定がない。これは本スキルが警戒する「AI生成デザインの定番3種」に流れやすい典型的な失敗パターン。DESIGN.md先出し + `roll_layout.py` による骨格抽選という本スキルの設計は、この失敗を避けるための具体的な対策になっている
- **関連性が薄い部分**: リポジトリの大半（FastAPI/React構成、複数LLMのオーケストレーション、画像生成/背景除去ツール連携、eval基盤、Docker運用）はAIプロダクト自体のエンジニアリングであり、静的サイト制作の知見としては流用できない
