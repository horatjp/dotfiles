# Pi を予備環境で使うとき

B の組で、Claude と Codex が使えないとき、または Claude・Codex 以外のモデルをチームに入れたいときだけ使う。

## 境界(必ず守る)
- **OpenRouter は有料の実行として扱う。** 1回ごとに払うので、起動の前に使ってよい上限(金額)をユーザーに決めてもらう。承認のないまま走らせない。
- **OpenCode Go は上限の金額を聞かず、使った量を記録する。** 定額なので、枠の中なら請求は増えない。起動直後(依頼を送る前)と終わり(`/quit` の前)に、Pi の画面下の枠の残り(5時間・週・月。どれも残りの割合)を記録して報告する。起動直後に、画面下の提供元が `opencode-go` であることを確かめる。`opencode-go` 以外なら止める(`openrouter` なら上限の承認を取り、従量課金の Zen の `opencode` などそれ以外はユーザーに上げる)(Pi が既定やセッションの復元でモデルを選ぶことがあるため)。
- **Go の枠を使い切らない。** 起動直後と終わりに枠の残り(5時間・週・月)を記録し、動いている間も区切りごとに残りを見て、どれかが 10% を下回る前に監督が止める(やり方は任せる。ユーザーが残したいと言った枠はその割合。10% より下げない。対象が曖昧なら 10% のまま相談する)。起動直後にどれかの枠がその割合以下なら依頼を送らず `/quit` してユーザーに相談する。Extra Usage が有効だと枠を使い切ったあと従量の残高へ切り替わる(未確認)ので、有効と分かったら止めてユーザーに上げる。
- **OpenRouter は費用を自動で見張る。** 承認した金額の上限の前に止められることを確かめてから起動する。Pi の画面の金額は実費や Go の枠とずれることがある。Go の枠の取得に失敗したときや `(stale)` と出たときは、起動せず、動いていれば止めてユーザーに上げる。
- **依頼文に、ページ取得・コマンド実行などの回数と、試し 1 回の時間の上限を書く。** Go・OpenRouter とも、上限の有無にかかわらず(回り続けて枠やクレジットを使い切らないため)。
- **モデルと提供元を固定する。** `openrouter/auto` などの自動振り分けは使わない(実装とレビューの別系統が守れなくなる)。系統は OpenRouter でなく提供元で書く。学習に使われる条件の安い版は使わない。
- **実装とレビューは別の提供元にする。** 予備でも同じ。
- **Pi の確認画面は、状態だけでは拾えないことがある。** 状態だけを見ず、画面全体を読んで `Dangerous command`・`Allow?` を探す。許可は [playbook §2](playbook.md) の確認画面の決まりに従う。
- **元に戻せない操作・秘密・本番はユーザーの承認。** 通常のチームと同じ。

## 使い方(目安。やり方はエージェントに任せてよい)
- 接続先はまず OpenCode Go(定額)。キーは Go 専用の変数 `OPENCODE_GO_API_KEY` に置き、`OPENCODE_API_KEY="$OPENCODE_GO_API_KEY" pi --provider opencode-go --model <Go の ID>` のようにその起動だけに渡す。`OPENCODE_API_KEY` は従量課金の OpenCode Zen と共通なので、端末に常時設定しない。Go に無いモデル・提供元を固定して過去と比べたい測定・検索の課題は OpenRouter(`--provider openrouter`)。402 が出たら同時に動かす Pi を減らし、続くならユーザーに相談する。Go の枠はモデルごとに違い、5時間の枠に当たりうる。
- 予備のチーム(その時点の目安。測定のたびに見直す):

| 役割 | モデル | 備考 |
|---|---|---|
| 監督 | DeepSeek V4 Pro | 依頼とまとめだけ |
| 実装 | DeepSeek V4.1 Flash | MiniMax M3.1 Flash を実装に使う場合は、レビューを別の会社のモデルにする |
| レビュー | MiniMax M3.1 Flash | 監督・実装と別の会社。重さと説明は監督が付け直す |
| 重いレビューの候補 | Kimi K3 | 未確認 |

effort は、どの役も `--thinking medium` から始める(未測定の目安)。起動の旗で必ず渡す。
予備なら監督も Pi にしてよい。Pi を使うときは、役割と、OpenRouter を使うなら金額をその都度ユーザーに決めてもらう。Pi の既定のモデルは Go のもの(例: MiniMax M3.1 Flash)にしておく。モデルを指定し忘れても OpenRouter に流れないようにするため。

- 起動: ペインの作成・配置・1体ずつの起動は人か監督が用意し、Pi にはさせない。Pi は同時に起動すると落ちることがあるので1体ずつ間をあける。同時に動かす Pi はまず2体まで。区切りごとに `/compact` を送る。終わりは Ctrl+C でなく `/quit`。
- 連絡: 依頼はファイル、声かけは `hc send`(TUI は `herdr agent prompt`)。Pi のスキルは `/skill:<名前>`。
- 依頼文に入れる: 完了の前に、仕様の境目の入力(エスケープ・ロケール・壊れた行・空の入力など)を自分で作り、期待する結果を先に書いてから実行して照合すること。画面のある成果物は、確かめられないとき「画面は未確認」と書かせ、完了と分ける。
- 依頼文に入れる(確認画面で止めないため): 作業中に作った一時フォルダは消さずに残し、パスを報告に書く。別のコマンド・スクリプト・他者への実行依頼で確認を避けて消さない。片付けが要るときは、監督が対象を確かめ、必要な承認を得てから行う。`hc send` の連絡文に `rm -rf` と書かない(Pi の `permission-gate.ts` は bash のコマンド全文を文字列として調べ、消す対象も引用符の中も区別しない。画面があれば確認画面を出し、無ければ止める)。それ以外の操作は「境界」のとおり。
- 向く役: 依頼を受けて返す役(実装・レビュー・事実確認)。出来は未確認なので、使うなら小さく試す。監督の原因の推定は、画面と記録で確かめてから使う。
