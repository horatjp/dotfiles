# Pi を予備環境で使うとき(multi-agent-playbook から分けたもの)

Claude と Codex が使えないとき、または Claude・Codex 以外のモデルをチームに入れたいときだけ読む。通常のチームでは使わない。経過・測定・試し A〜G・旧版の全文は `<ai-watch>/docs/knowledge/multi-agent-trials.md`(根拠の置き場。ここに新しい決まりは書かない)。

## 境界(必ず守る)
- **OpenRouter は有料の実行として扱う。** 1回ごとに払うので、起動の前に使ってよい上限(金額)をユーザーに決めてもらう。承認のないまま走らせない。
- **OpenCode Go は上限の金額を聞かず、使った量を記録する。** 定額なので、枠の中なら請求は増えない(ユーザー、2026-11-07)。起動直後(依頼を送る前)と終わり(`/quit` の前)に、Pi の画面下の枠の残り(5時間・週・月。どれも残りの割合)を記録して報告する。起動直後に、画面下の提供元が `opencode-go` であることを確かめる。`openrouter` だったら OpenRouter として扱い、止めて上限の承認を取る(Pi が既定やセッションの復元でモデルを選ぶことがあるため)。
- **Go の枠を使い切らない。** Extra Usage が有効だと、枠を使い切ったあと止まらずに従量の残高へ切り替わる(`<ai-watch>/docs/knowledge/opencode-go.md`。要約で原文は未確認)。無効と確かめた記録(opencode-go.md に日付つき)が無い間は、5時間・週・月のどれかの残りが、その枠に当てる割合(ふだん 10%、下の指定で上げた枠はその割合)を下回る前に止める(起動直後にどれかの枠がその割合以下なら、依頼を送らず `/quit` してユーザーに相談する)。この 10% は3つの枠すべての最低限で、ユーザーが枠を残したいと言ったときは、どの枠を何%残すかを聞き、それが 10% より多い枠だけその割合に上げる(10% より下げない。対象が曖昧なら 10% のまま相談する)。「従量へ切り替わるのは枠を使い切ったあとだけ」は要約に頼った前提で、原文で確かめるまでは要確認。
- **OpenRouter は費用、Go は枠の残りで自動で見張る。** OpenRouter は承認した金額の上限、Go は上の割合の前に止められることを確かめてから起動する(Go で Extra Usage が無効と確かめ済みで、残す割合の指定も無いときは、記録だけでよい)。Pi の画面の `$` は自己申告で、実費や Go の枠とずれることがある(`<ai-watch>/docs/knowledge/multi-agent-trials.md`)。Go の画面下の残りは公式の資料に無い入口から取っている(opencode-go.md「使用量の取り方」)ので、取得に失敗した・`(stale)` と出たときは残りを確かめられない経路として扱い、起動せず(動いていれば止めて)ユーザーに上げる。確かめられない経路は起動せず、ユーザーに上げる(herdr-app での自動の見張りと停止は未確認)。
- **依頼文に、ページ取得・コマンド実行などの回数の上限を書く。** Go・OpenRouter とも、上限の有無にかかわらず(回り続けて枠やクレジットを使い切らないため)。
- **モデルと提供元を固定する。** `openrouter/auto` などの自動振り分けは使わない(実装とレビューの別系統が守れなくなる)。系統は OpenRouter でなく提供元で書く。学習に使われる条件の安い版は使わない。
- **実装とレビューは別の提供元にする。** 予備でも同じ。
- **Pi の確認画面は、状態が idle のままでも出る。** 状態だけを見ず、画面全体を読んで `Dangerous command`・`Allow?` を探す。許可は playbook の確認画面の決まりに従う。
- **元に戻せない操作・秘密・本番はユーザーの承認。** 通常のチームと同じ。

## 使い方(目安。やり方はエージェントに任せてよい)
- 接続先: まず OpenCode Go(定額。`OPENCODE_API_KEY="$OPENCODE_GO_API_KEY" pi --provider opencode-go --model <Go の ID>`、~/.env は 1Password のパイプなので zsh のペインで読む)。Go に無いモデル・提供元を固定して過去と比べたい測定・検索の課題は OpenRouter(`--provider openrouter`、1回ごとにクレジットを使う。402 が出たら同時に動かす Pi を減らし、続くならユーザーに相談)。Go の枠はモデルごとに違い、5時間の枠に当たりうる(`<ai-watch>/docs/knowledge/opencode-go.md`)。Pi の画面の金額は Go の枠の消費ではない。
- 予備のチーム(その時点の目安。測定のたびに見直す): 監督(依頼とまとめだけ)DeepSeek V4 Pro、実装 DeepSeek V4.1 Flash、レビュー MiniMax M3.1 Flash(監督・実装と別の会社。重さと説明は監督が付け直す)、重いレビューの候補 Kimi K3(未確認)。予備なら監督も Pi にしてよい。Pi を使うときは、役割と、OpenRouter を使うなら金額をその都度ユーザーに決めてもらう。
- 起動: ペインの作成・配置・1体ずつの起動は人か監督が用意し、Pi にはさせない。Pi は同時に起動すると落ちることがあるので1体ずつ間をあける。同時に動かす Pi はまず2体まで。区切りごとに `/compact` を送る。終わりは Ctrl+C でなく `/quit`。
- 連絡: 依頼はファイル、声かけは `hc send`(TUI は `herdr agent prompt`)。Pi のスキルは `/skill:<名前>`。
- 依頼文に入れる: 完了の前に、仕様の境目の入力(エスケープ・ロケール・壊れた行・空の入力など)を自分で作り、期待する結果を先に書いてから実行して照合すること。画面のある成果物は、確かめられないとき「画面は未確認」と書かせ、完了と分ける。
- 向く役: 依頼を受けて返す役(実装・レビュー・事実確認)。出来は未確認なので、使うなら小さく試す。監督の原因の推定は、画面と記録で確かめてから使う。
