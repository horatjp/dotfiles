# 依頼: <件名>のレビュー(<レビュー役の agmsg 名>)

あなたはレビュー担当です。ファイルは変えないこと(報告ファイルの作成だけ可)。コミットしない。有料の実行・API 呼び出しはしない。読むのは差分と、食い違いの確認に要る節だけ。
<試しの実行が要るなら: 一時フォルダでのスクリプトの試しは可>

- 参加(未参加の相手に頼むときだけ。参加済みなら消す): agmsg スキルで、チーム <チーム> に参加する。`join.sh` で team=<チーム>、name=<名前>、type=<claude-code|codex>、project=<フォルダ>。そのあと actas <名前>。ほかのチームには登録しない。参加後は監督が `team.sh <チーム>` で載ったかを確かめる
- 操作が権限の確認で止められたら、消す・上書きする操作を含まず、依頼の範囲内で、権限確認・拒否の理由(ネットワーク・本番・秘密・書き込み先など)や承認の要件を回避しない代わりの方法で同じ結果が得られるかを確かめて進めるか(理由や許可範囲が不明なら進めず報告する)、止まって報告する。監督は止められた操作を代わりに実行しない(権限の決まりを迂回しないため)。代わりの方法でも判断がつかないものはユーザーに上げる
- 計画: <計画ファイルのパス>、報告: <impl-….md>(再確認のときは最新の impl-…-N.md)
- 対象: `git -C <リポジトリ> diff`、<新しいファイルがあれば `git -C <リポジトリ> status --short -- <パス>`>
- 見る点:
  1. <計画の中身が入っているか、根拠と合っているか>
  2. <playbook の他の節との食い違い(合図は1つ・待ち方・参加の頼み方・権限で止められたとき・hc send の `--`)>
  3. <境目の入力での挙動。自分でも動かして確かめる>
- 範囲(秘密・お金・止める条件・壊れた入力を点検させるときは必ず書く): 守る相手 <…>、守らない相手 <…>(理由)、動かす環境 <…>。範囲の外の指摘は数えない
- 指摘: P1(直さないと壊れる・危ない)/ P2(直すべき)/ P3(任意)、根拠は ファイル:行、直し方の案。推測は「要確認」
- 返す先: 本文は <報告ディレクトリ>/review-<名前>.md(再確認は review-<名前>-2.md など)。最後の行は飾りなしの `P1=n P2=n P3=n`(再確認は `再確認 P1=n P2=n P3=n`)。
  - 作業役(<agmsg 名>)には件数とパスを agmsg で(作業役が Claude なら agmsgd で届くので声かけは要らない。Codex なら `hc send <端末> -- '受信箱を1回確認して…'`)
  - 監督(<agmsg 名>)には集計を1行「集計: P1=n P2=n P3=n 対象=<名前> 種類=初回|再確認 本文=<パス>」(agmsgd で届くなら hc send の合図は要らない)
