agmsg を使わないチーム・agmsgd が無いときは、このひな形を使わず playbook §5 の「終わりの合図は報告ファイルで受け取る」の形で依頼文を書く。

# 依頼: <件名>(<作業役の agmsg 名>)

計画: <計画ファイルのパス> を必ず読む(<中身・置き場所・完了条件・禁止事項>)。

- 参加(未参加の相手に頼むときだけ。参加済みなら消す): agmsg スキルで、チーム <チーム> に参加する。`join.sh` で team=<チーム>、name=<名前>、type=<claude-code|codex>、project=<フォルダ>。そのあと actas <名前>。ほかのチームには登録しない。参加後は監督が `team.sh <チーム>` で載ったかを確かめる
- 触るファイル: <パスを列挙。これ以外は触らない>
- <原本を先に直し写しに同じ変更を入れる、など順序の決まりがあれば。なければ消す>
- 操作が権限の確認で止められたら、消す・上書きする操作を含まず、依頼の範囲内で、権限確認・拒否の理由(ネットワーク・本番・秘密・書き込み先など)や承認の要件を回避しない代わりの方法で同じ結果が得られるかを確かめて進めるか(理由や許可範囲が不明なら進めず報告する)、止まって報告する。監督は止められた操作を代わりに実行しない(権限の決まりを迂回しないため)。代わりの方法でも判断がつかないものはユーザーに上げる
- やらないこと: git commit / push / reset、有料の実行、触るファイル以外の変更
- <境目の入力(空・欠け・失敗・短い入力・フォルダなど)と、それぞれの試験を完了条件に並べる>

## 終わったら

1. 報告は agmsg の本文で <監督の agmsg 名> へ返す。1行目は飾りなしの `実装完了`、続けて <項目ごと: どこに何を入れたか、試した結果>。本文が約500字を超えるとき(表・長い根拠の一覧・コマンドの出力を含むときも)だけ <報告ディレクトリ>/impl-<名前>.md に書き、agmsg には1行目を `実装完了` にした要点3行以内とパスを送る
2. 監督(agmsgd で受ける)へは agmsg で届くので、`hc send` の合図は要らない
3. agmsg で <レビュー役の agmsg 名> にレビューを頼む(依頼文は <req-review-….md のパス>)。相手が Codex のときだけ、送ったあと `hc send <レビュー役の端末> -- '受信箱を1回確認して、届いている依頼を進めてください。'`
4. 指摘が来たら直し、同じ形で報告する(1行目は `実装完了`。ファイルにするときは新しいファイル impl-<名前>-2.md など)。レビュー役に再確認(Codex なら声かけも)、監督に報告
