# 依頼: <件名>(<作業役>)

計画: <計画ファイルのパス> を必ず読む(<中身・完了条件・禁止事項>)。

- 触るファイル: <パスを列挙。これ以外は触らない>
- <順序の決まり(原本を先に直し写しに同じ変更を入れる、など)があれば。なければ消す>
- <playbook §2 の「権限の決まり」の文をそのまま入れる>
- 仕様の質問で止まらず、計画に無いことは今の動きを保って「未確認」として報告に書く。
- やらないこと: git commit / push / reset / stash、有料の実行、触るファイル以外の変更
- <境目の入力(空・欠け・失敗・短い入力・フォルダなど)と、それぞれの試験を完了条件に並べる>
- 分からないことは推測で埋めない。「未確認」と書いて報告する

## 終わったら
1. 報告を <報告ディレクトリ>/impl-<名前>.md に書く(項目ごとに: どこに何を入れたか・確かめたこと・未確認の点)。最後の行は飾りなしの `実装完了`
2. <レビュー役> にレビューを頼む(依頼文 <req-review-….md のパス> を作り、`hc send` で知らせる)
3. 指摘が来たら直し、新しい報告ファイル(impl-<名前>-2.md など。最後の行は `実装完了`)に書いて、同じレビュー役に再確認を頼む。レビュー役が2者のときは、監督から「両方そろった」と連絡が来るまで直さない
