# マルチエージェントの起動と監督

監督(このセッション)は原則として自分では実装しない。作業を分け、役割ごとのエージェントを herdr のペインで起動し、依頼はファイル、声かけ・ペインどうしの会話は `hc send`(TUI の herdr は `herdr agent prompt`)で行う。レビューを通ったものだけを監督がコミットする。決まりは目的と境界だけで、細部はエージェントの自律に任せる。

- 決まりの正: [references/playbook.md](references/playbook.md)(目的・境界・チーム表・連絡と見張り・依頼文に書くこと・記録)。起動の前に読む
- 道具: ペインの操作は `herdr-app` スキル(herdr-app の中)または `herdr` スキル(TUI)。どちらかは `herdr-app` スキルの「どちらを使うか」で決める。herdr の外の相手と話すときだけ `agmsg` スキルを使ってよい

## 手順
1. **チームを決める。** playbook §3 の表から役割とモデルを選ぶ。実装した人とレビューする人は別系統(提供元が違う)にする。常に動かすのは3体まで。起動の前に Claude と Codex の残りの枠を見る(playbook §3)。
2. **計画を書いてユーザーに見せ、了承を得てから起動する。** 項目・担当・順番(触るファイルが重ならないように)・完了条件・禁止事項を、プロジェクト内のファイル(例: `reports/<日付>/PLAN.md`)に書く。計画のコミットは、門番を通った変更と一緒にする。
3. **起動する。** ペインを開き(監督のペインは上下に分けない。ほかは右側にまとめる)、依頼文を書いて `hc send` の1行で知らせる。依頼文の中身は playbook §5 とひな形。作業役・レビュー役の依頼文には playbook §2 の「権限の決まり」の文をそのまま入れる。herdr-app のペインの開き方・待ち方は `herdr-app` スキル。
4. **見張る。** 止まり(`blocked`・`error`)・終わり・見張り自体の失敗に気づけるようにする(playbook §4)。止まっているエージェントには声をかける。確認画面は playbook §2 の範囲の読み取りだけ監督が許可し、それ以外はユーザーに上げる。終わりは報告ファイルの最後の行(`scripts/wait-signal.sh <報告ファイル> <impl|review> [秒数=600]`。合図あり0・時間切れ1・失敗2)。報告はまず要点と集計の行だけ読み、本文や画面は門番で根拠を確かめるとき・P1/P2 が残るとき・止まったときに開く。
5. **門番をする。** レビューの集計が P1=0・P2=0、テストが通る、差分が範囲内、根拠の数字を1つは自分で確かめた、がそろった項目だけを関心ごとに分けてコミットする。監督が目で見ただけの変更はコミットしない。2者にレビューさせている間は、両方が返るまで差分を直さない。両方返ったら作業役に知らせる。
6. **有料の実行・元に戻せない操作はユーザーの承認を得て、監督が専用の端末で行う。** 費用は上限を決めて、超えそうなら止める。herdr-app でも hc の専用端末(pane.split で開いた端末)で行ってよい。承認・上限は毎回ユーザーに取る。終わりは `hc wait <t>`、止めるのは `hc kill <t>`。費用を画面から自動で見張って上限の前に止める必要がある実行(Pi の予備環境、playbook §7)は、herdr-app での手順が未確認なので TUI で行う(TUI が動いていなければユーザーに上げる)。
7. **報告して片付ける。** 区切りごとに、結果・判断・ユーザーに決めてほしいことを専門用語なしで伝える。終わったら見張りを止め、自分が開いたペインを閉じる。進捗の記録(STATUS・PLAN)を節目で更新し、チームを1回動かしたら原本(ai-watch)の `docs/knowledge/multi-agent-runs.md` に振り返りの1行を足す(書き込みを許された範囲のときだけ)。

## 予備環境(Pi)
Claude と Codex が使えないときだけ。費用の上限と自動の見張り・提供元の固定・承認は境界なので、[references/pi.md](references/pi.md) を確かめてから。
