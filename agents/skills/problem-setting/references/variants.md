# 軽い使い方(取捨・役割の定義・差分の説明)

フルの6ステップほど重くない依頼で使う。どれも結論はユーザーが決め、AI は判断材料と推奨を示して止まる。
記録の置き場はフルと同じ(SKILL.md の「記録」)。

## 依頼・要望の取捨

上司の依頼、顧客の要望、チームのアイデアを「やるべきか」で判断する。問いは「できるか」ではなく「やる価値があるか」。

1. その依頼が何の問題を解くためのものかを確かめる(分からなければ依頼者に聞く質問を用意する)
2. 次の軸で評価する(数字が無ければ大・中・小と根拠):
   - その困りごとを持つ人は何人(どれくらいの割合)か
   - 解かないと、どの指標がどれだけ悪いままか
   - かかる手間・費用
   - 期待できる改善
   - ほかの仕事を後回しにしてまで今やる理由があるか(機会費用)
3. 結論を3つのどれかで出す: **やる / 今はやらない / 別の方法でやる**(もっと安く同じ問題を解く方法)
4. 依頼者への説明文を添える:「〇〇を優先したほうが△△が大きく改善するため、今回は□□とします。理由は…」

複数の要望を並べるときは表にする(要望・解く問題・軸ごとの評価・結論・理由)。声の大きさや届いた順で並べない。

## 役割を差分で定義する

職名やタスクの一覧(「マーケ担当: SNS・広告・メルマガ」)ではなく、**自分が関わることで、誰がどんな状態から
どんな状態に変わるか**で役割を書く。

```
<誰>を、<今の状態>から、<目指す状態>まで連れていく
例: 製品を知らない見込み客を、自分に合うかどうか判断できる状態まで連れていく
```

1. 役割の受け手(誰の役に立つのか)を決める
2. 受け手の「前」と「後」の状態を書く
3. その差分を測る指標を1〜2個決める
4. 今やっているタスクを並べ、差分に効くか・効かないかで仕分ける(効かないものは、やめる・減らす候補として示す)

## 生んだ差分を説明する

作業の量(「レポートを月20本作った」)ではなく、**関わる前と後で、誰の判断や行動が変わったか**で書く。

1. やったことを並べる
2. それぞれについて「その結果、誰の何が変わったか」を聞く(変わっていなければ正直に「変化なし」とする)
3. 変化を数字か具体的な行動で書く(例:「広告の配分を、感覚ではなく顧客の継続期間を基準に決められるようになった」
   「問い合わせ対応が月100時間 → 50時間」)
4. 変化がまだ無いものは、どうすれば差分になるかを次の一手として書く
