# ヒアリングガイド(わからないことがなくなるまで)

計画の質はヒアリングの質で決まる。目標は「チェックリストの全項目が、
ユーザーの回答またはユーザーが承認した提案で埋まっている」状態。
推測やデフォルト値で黙って埋めた項目が1つでも残っていたら、ヒアリングは未完了。

## 進め方の原則

- **1回に1トピックだけ聞く。** 複数の質問を箇条書きで一括送信しない。
  回答を受けてから、その回答が生む次の疑問を掘る
- **選択式にできる質問は選択肢を提示する**(AskUserQuestion のような
  選択式質問ツールが使える環境では積極的に使う)。自由回答はユーザーの負担が大きい
- **専門用語で聞かない。** 「RBACは必要ですか?」ではなく
  「管理者と一般ユーザーで、できることを分けますか?」と聞く
- **具体例で確認する。** 抽象的な合意は後でずれる。
  「例えば、田中さんが会議室Aを10時に予約しようとして既に埋まっていたら、どうなるべきですか?」
- **答えは要約して返す。** 「〜という理解で合っていますか?」で認識合わせをしてから次へ
- **「お任せ」への対応**: 丸投げのまま進めず、具体案を1つ作って
  「この内容で進めます。よろしいですか?」と承認を取る。承認された提案は
  「ユーザー確認済み」として扱ってよい
- **答えられない質問が出たら**: その場で決めさせず、「仮案+再検討の条件」を提案して
  合意を取り、docs/decisions/ に記録する前提でマークしておく

## チェックリスト(全項目を埋める)

順番は目安。会話の流れに合わせて入れ替えてよいが、飛ばさない。

### 1. 目的
- 誰の、どんな課題を解決するのか
- 今はその課題をどう処理しているのか(Excel、紙、既存システム…)
- 何ができたら「成功」なのか

### 2. 利用者
- 誰が使うか(社内/社外、顧客/スタッフ)
- 人数規模(5人と5000人では設計が変わる)
- 管理者と一般利用者で、できることを分けるか(ロール分離の要否)
- 利用者のITリテラシー・利用環境(PC/スマホ、社内ネットワーク限定か)

### 3. 管理対象(エンティティ)
- 何を管理するのか(名詞を拾う: 予約、商品、会員…)
- それぞれのデータ量の見込み(数十件か数百万件か)
- データの持ち主は誰か(ユーザーごとに分離するか、全員で共有するか)

### 4. 主要ユースケース
- 主要な操作を5個前後(CRUD以上のビジネスルールを優先して掘る:
  重複禁止、締切、承認フロー、在庫引き当て、キャンセル規定…)
- 各ユースケースの「例外時にどうなるべきか」を具体例で確認する

### 5. 認証・アカウント
- ログインは必要か
- アカウントはどう作られるか(自己登録 / 管理者が招待 / 既存の社内認証と連携)
- パスワード以外の要件(Google ログイン、2要素認証など)

### 6. 外部連携
- メール・通知(予約確認メール等)は必要か
- 決済はあるか
- 既存システム・既存データとの連携や移行はあるか
- 外部にAPIを公開する予定はあるか

### 7. 非機能要件
- 対応デバイス(PCのみ / スマホ対応必須)
- 多言語対応の要否
- 性能・可用性への特別な要求(通常のWebアプリ水準でよいか)

### 8. 運用・インフラ
- デプロイ先の希望・制約(VPS / Vercel / Cloudflare / 社内サーバー / 指定なし)
- 予算感(月額でいくらまで許容か。無料枠希望か)
- 運用者は誰か(障害対応・バックアップを誰が見るか)

### 9. 既存資産
- 既存のコード・デザイン・ドメイン(URL)・データはあるか
- 流用するもの / 捨てるものの切り分け

### 10. スコープ外
- 「今回はやらないこと」を明文化する(次期フェーズ送りの機能、対応しない例外)。
  ここが曖昧だと実装AIが善意で拡大解釈する

## 記録

- 回答は都度 `docs/requirements.md` のドラフトに反映する。会話にしかない情報を残さない
- 全項目が埋まったら、requirements.md の全文をユーザーに提示して最終確認を取る。
  ここで出た修正・違和感は新たなヒアリング項目として掘り直す
- 「仮案+再検討の条件」で合意した項目は、下地展開時に `docs/decisions/`
  (再検討の条件つき)へ記録する

## requirements.md の構成

```markdown
# 要件

## 目的(誰の・何を・成功の定義)
## 利用者とロール
## 主要エンティティ
## 主要ユースケース(ビジネスルール込み)
## 認証・アカウント
## 外部連携
## 非機能要件(デバイス、規模、性能)
## 運用・インフラ(デプロイ先、予算、運用者)
## 既存資産(流用・移行するもの)
## スタック(フェーズ2で追記)
## スコープ外
```
