# AGENTS.md

**モットー:** 「安全に、シンプルに、組み合わせ可能に」

## コミュニケーション

- 出力はユーザーの言語（通常は日本語）で行う。
- リクエストに出力・API・UX・セキュリティへ影響する複数の解釈がある場合は、黙って選ばずすべて提示する。
- 挙動・セキュリティに確信が持てないときは推測せず質問する。外部影響のない実装詳細は進めながら自己修正してよい。
- 同意をデフォルトにしない。おかしいと思ったら根拠を添えて反論し、代替案を提示する。
- 頼まれた作業が残っている間は止まらない。エラーや時間切れは原因を調べて乗り越え、失敗した操作のやり直しは確認なしでしてよい。有料・秘密・本番・削除・外へ送る操作は、前に了承を取る。
- 報告は、途中を見ていない人が読んで分かるように書く。大事なことを最初に置き、作業中に作った呼び名や略語は使わない。

## コード

- 変更は最小限・可逆に。頼まれていない機能や、一度しか使わないコードへの抽象化を持ち込まない。
- 続けて使うコードの業務ルール・計算は、入出力から分けた純粋な関数にし、境目の入力を含むテストを先に書く。要件から決まらない所は緩いテストで済ませず、聞く。UI・外部連携の配線や一度きりのスクリプトには求めない。
- 自明でないロジックや設計判断にはコメントを付ける。慣習が許すプロジェクトではファイルヘッダー（どこ / 何 / なぜ）を書く。
- ファイルは目安300行以下。ただし凝集性を優先し、人工的に分割しない。
- コミットは関心ごとにアトミックに（依存 / 設定 / コード / テスト / 文書）。

## コンテキスト

- 道具の出力は入口で絞る。ただし判断に要る範囲は必ず読み、足りなければ推測せず追加で確かめる。
- 大きなファイルは検索してから、該当箇所と判断に要る前後だけ読む。手元にある変わっていない内容は取り直さない。他者が変えたファイルは差分と、その影響を判断できる周辺を読む。
- 長い出力（テスト・ビルド・ログ）は、書き込みを許された場所があればファイルに保存し（なければ必要な部分に絞って取得し）、元のコマンドの終了コード・成否の件数・失敗箇所と、警告・打ち切りなど判断に要る点を出す。
- 結論だけ要り途中の出力を二度と使わない調べもの（Web・広い探索・長いログ）は、委譲が許され、少ない入力で独立して終わる場合に限り別のエージェントに渡す。受け取るのは結論・根拠の場所（パス・行・URL・見出し）・未確認の点だけ。1〜3回の道具で済むものは自分でやる。委譲された側は、明示されない限り再委譲しない。
- 続きに要る決定・未解決の点・次の一手は、節目で既存の記録（STATUS など）に残す（書き込みを許された範囲で）。ユーザーに /clear・/compact は頼まない。

## ツール

- Cloudflare を操作するときは、プロジェクトに Wrangler 設定ファイル（`wrangler.jsonc` / `wrangler.toml`）がない限り `cf` CLI を使う。ライブログ（`tail`）など `cf` 未対応の操作は `npx wrangler` を使う。
