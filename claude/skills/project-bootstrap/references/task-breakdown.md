# タスク分解ガイド(実装AIへの指示書)

計画と実装は別のAIセッションが担う。このスキル(計画側)の最後の仕事は、
実装作業を「会話履歴を知らないAIがそのまま着手できる指示書」に分解すること。
セッションをまたぐ情報伝達は**ファイルのみ**。「会話で伝えたこと」は存在しないものとして書く。

## タスク指示書の置き場所と形式

`tasks/` ディレクトリに1タスク1ファイルで置く。ファイル名: `NNN-短い題名.md`(連番)。
`tasks/` は計画側→実装側のタスク受け渡し専用。プロジェクトのISSUE管理とは混ぜない。

```markdown
---
status: todo   # todo | in-progress | done | blocked
depends: [001]
---
# 002: 予約APIの実装

## 目的
予約の作成・一覧・キャンセルAPIを実装する

## スコープ
- POST /api/reservations(重複チェック込み。docs/api.md 参照)
- GET /api/reservations?scope=mine
- DELETE /api/reservations/:id(本人のみ)

## スコープ外
- 管理者向けの全予約一覧(003で扱う)

## 受け入れ条件
- [ ] docs/api.md の仕様どおりのステータスコード・レスポンス形式
- [ ] 重複予約が409になる結合テストがある
- [ ] 未認証が401になるテストがある

## 参照
- docs/schema.md, docs/api.md
- docs/rbac.md(ロール分離がある場合。認可を扱うタスクでは必須)
- docs/ai/references/implementation.md(実装規約)
- docs/ai/decisions/YYYY-MM-DD-stack.md
```

## 書き方の要点

- **受け入れ条件はテスト可能な形で書く。**「ちゃんと動く」は受け入れ条件ではない
- **スコープ外を明記する。** 実装AIの善意の拡大解釈が一番の手戻り原因
- 1タスクは実装AIの1セッションで完了する粒度に切る(目安: 生成コード数百行以内)
- 参照には必ず実装規約(`docs/ai/references/implementation.md` 等)と
  関連する決定記録を含める。実装AIに「探させる」のではなく「渡す」
- タスク001は必ず「プロジェクト初期化 + スキーマ + マイグレーション + シード」にする。
  以降は依存の向き(認証 → API → 画面)に従って切る

## 実装AIに期待する動き

実装側の約束事(設計を勝手に変えない・各段階で動作確認・完了報告)は、
フェーズ4で展開先の `AGENTS.md` に追記済み(`assets/agents-md-append.md`)。
タスク指示書に書き写す必要はない。タスク固有の注意(依存タスクの成果物、
触ってはいけない領域など)があれば「スコープ外」や「参照」に明記する。

## 完了報告の形式(実装側がタスクファイル末尾に追記)

```markdown
## 完了報告 (2026-07-03)
- 実装: src/app/api/reservations/ 一式、テスト12件(全パス)
- 判断した点: キャンセルは物理削除でなく status=CANCELLED に(履歴が残るため)→ 要承認
- 詰まった点: docs/ai/research/prisma-timezone.md に記録
```

「判断した点」はユーザー(または次の計画セッション)がレビューし、
承認したら `docs/ai/decisions/` に昇格させる。
