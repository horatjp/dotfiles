## 構成（14セクション+付録）

## 良い点・転用ポイント

1. **Design Read（1行宣言）**: コードを書く前に「〜向けの〜として読んだ。〜系の言語で〜に寄せる」と1行で宣言。曖昧なら質問は**1つだけ**、推論できるなら聞かずに進む
2. **3つのダイヤル**: DESIGN_VARIANCE / MOTION_INTENSITY / VISUAL_DENSITY を1-10で設定し、以降の全判断をこの値でゲート。ブリーフの語彙（"minimalist"→5-6/3-4/2-3等）からダイヤル値を推論する対応表つき
3. **実在するデザインシステムは公式パッケージを使う**: Fluent/Material/Carbon/Polaris/GOV.UK等の対応表。「公式があるものを手書きCSSで再発明しない」「1プロジェクト1システム」という誠実さルール
4. **AI Tells（AIっぽさの兆候）を具体的に列挙・禁止**:
   - 視覚: ネオングロー、純黒#000、過飽和アクセント、グラデ文字
   - レイアウト: 3枚等幅フィーチャーカード禁止（2列ジグザグ・非対称グリッドで代替）
   - コンテンツ: "John Doe"等の汎用名・完璧すぎる数字（99.99%）・"Acme"系ブランド名・"Elevate/Seamless"系動詞を禁止 →「organicで雑味のあるデータ」を使う
   - リソース: 手書きSVGアイコン禁止（Phosphor等を使う）、div製の偽スクリーンショット禁止、切れたUnsplashリンク禁止（picsum.photos/seed/を使う）
   - ヒーローの `V0.6` `BETA` 等のバージョンラベル、`01 / INDEX` 等のセクション番号アイブロウも禁止
5. **最終プリフライトチェック**: 出荷前の自己検査リストを持つ
6. **スコープを明示**: 「ダッシュボード・データテーブル・複数ステップの製品UIは対象外」と冒頭で宣言。全ルールは文脈依存で自動発火しないと明記

## セクション4（バイアス補正）の詳細

- **タイポグラフィ規律**:
  - Inter をデフォルトにしない（Geist / Outfit / Satoshi 等を先に検討。ニュートラル指定や公共系なら Inter 可）
  - **セリフ体はデフォルト禁止**:「クリエイティブ=セリフ」はAIの最頻の癖。エディトリアル/ラグジュアリー/出版/ヘリテージで理由を言語化できるときだけ
  - Fraunces / Instrument Serif（LLMが好む2大ディスプレイセリフ）は既定値として明示的に禁止
  - 見出し内の強調は**同一ファミリーのイタリック/ボールド**。サンズ見出しにセリフ1語を混ぜる混植強調は素人技
  - イタリックのディセンダー（y g j p q）は `leading-none` でクリップされる → 最低 `leading-[1.1]` + 余白確保
- **カラー規律**:
  - アクセントは最大1色、彩度80%未満が既定。LILAルール: AIパープル/ネオングラデは既定禁止
  - **カラー一貫性ロック**: 一度決めたアクセントはページ全体で使う。セクション7で突然青いCTAを出さない
  - **プレミアム消費財パレット禁止**: ベージュ/クリーム背景+真鍮/クレイ/オックスブラッドアクセント+エスプレッソ文字（#f5f1ea + #b08947 + #1a1714系）はAIの二番目に多い癖として具体的hexで禁止。代替: Cold Luxury / Forest / Black and Tan / Cobalt+Cream / Terracotta+Slate / モノクロ+単色ポップ等をローテーション
- **レイアウト**: VARIANCE>4なら中央寄せヒーロー回避（スプリット/左寄せ+右アセット/非対称）。エディトリアル/マニフェスト系は中央OK
- **カード規律**: 標高が実際の階層を伝えるときだけカード化。それ以外は border-t / divide-y / 余白でグルーピング。影は背景色相に合わせてティント（純黒ドロップシャドウ禁止）

## 教訓

- 禁止リストは「なぜAIがそれをやりがちか」を踏まえた実戦的な粒度で書くと効く
- ダイヤル方式は「トーン調整を会話で上書きできる」構造として優秀
- 1206行は大きすぎる面もある。本体は判断フロー、詳細表はreferencesに逃がすのが良い
