# 実行サーフェス選択ガイド

同じロール(roles/配下の定義)でも、「どこで実行するか」はタスクの性質によって変わります。
毎回悩まないよう、以下の判断フローを基準にしてください。

## 判断フロー

```
Q1. 複数人が日常的に使う「窓口」か?(全社員向けFAQなど)
  YES → 共有Project(チームで共有)または Bot化(APIでSlack等に常設)
  NO  → Q2へ

Q2. 人がチャットを開かず、定期的・自動的に動く必要があるか?
  YES → API/Agent化(ROLE.mdをシステムプロンプトにしてスケジュール実行)。
        ファイル操作を伴う場合は Claude Code + スケジューラでも可
  NO  → Q3へ

Q3. ファイル操作・自動化・ナレッジの自動更新(learnings.mdへの追記等)が必要か?
  YES → Claude Code(ROLE.md を .claude/skills/ として配置しコマンドラインから実行)
  NO  → Q4へ

Q4. 複数ステップ・複数ファイル・複数ツール(検索+資料作成+表計算など)にまたがるか?
  YES → Cowork(ロール定義を渡してタスクとして依頼)
  NO  → Claude Projects(ロールをカスタム指示に設定したProjectで会話)
```

※共有性(Q1)と定期性(Q2)を先に判定するのは、これらが「誰が・いつ起動するか」という
排他的な分岐だからです。「定期実行かつファイル操作あり」のようなタスクが
判断不能になるのを防ぎます。

## 具体例で当てはめる

| やりたいこと | 結論 |
|---|---|
| 「この就業規則の条文の意味を教えて」(自分だけ・単発) | Projects |
| 全社員がいつでも人事FAQに質問できる窓口を作りたい | 共有Project または Bot化(API) |
| 「先週のSNS投稿を分析して来月の投稿案を10本作って」 | Cowork |
| 「経理ロールのlearnings.mdを月次で自動整理したい」 | Claude Code |
| 「毎朝9時に在庫状況をチェックして異常があれば通知」 | API/Agent化(ファイル更新も伴うなら Claude Code + スケジューラ) |

**迷ったら軽い方(Projects)から試し、足りなくなってから重い方に上げてください。**
最初から全部作り込むのはオーバーエンジニアリングです。

## サーフェスを跨いでも一貫性を保つ(重要)

**git上の `ROLE.md` / `knowledge/` を唯一の正とします。** Projects のカスタム指示や
アップロード済みナレッジは「コピー」なので、元を更新すると必ず乖離が始まります。

`ROLE.md` または `knowledge/` を更新したら:

1. `ROLE.md` frontmatter の `updated_at` を今日の日付に更新する
2. frontmatter の `surfaces` に列挙されたサーフェスすべてに反映する
   - **Projects**: カスタム指示を貼り直し、変更のあったナレッジを再アップロード
   - **Claude Code**: リポジトリを pull すれば反映される(最もドリフトしにくい)
   - **API/Agent**: システムプロンプトを再デプロイ
3. どの版で動いているか怪しい時は、サーフェス側に「あなたの定義の updated_at はいつか」と
   聞けば確認できる

**learnings.md の現実的な運用**: 自動追記ができるのは Claude Code 実行時のみです。
Projects で使う場合は、セッション終わりの付随質問(Q3)で気づきを拾い、
ユーザーが週次/月次で `learnings.md` に転記してください。

## さらに連携層が必要になるサイン

以下に当てはまったら、`governance/coordination.md` を参照して連携層の追加を検討してください。

- 複数ロールの結果を突き合わせて1つの結論を出したい → 疑似会議(レベル1。まずはこちら)
- 独立した複数の見立てが欲しい → 別セッション実行(レベル1.5)
- 複数ロールが本当に別々のタイミング・ペースで動く必要がある、
  「Aの完了を待ってからBを始めたい」という依存関係がある → GitHub Issues連携(レベル2)
