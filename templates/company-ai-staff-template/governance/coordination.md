# 連携層ガイド:ロール同士をどう協働させるか

複数のロール(業務・人格どちらでもよい)の視点を組み合わせたい時の、3段階のレベル感です。
**下のレベルから順に試し、足りなくなってから上げてください。**

## レベル1: 疑似会議(まずはこれ。追加インフラ不要)

1つのセッションの中で、複数ロールの視点を演じ分けて議論させる方法です。
`skills/meeting-simulation/SKILL.md` を使います。

```
例:「hr-faq の視点と、strategy-advisor の視点で、リモートワーク制度の改定案について
議論させてください。それぞれの主張を出した上で、論点を整理してください」
```

**向いている場面**
- 視点の違いをその場で比較したいだけ(実際に別々に作業を進める必要はない)
- 結論を急いで出したい(同一コンテキストなので速い)

**限界(必ず理解しておく)**
- 全視点を同じAIが同じコンテキストで演じるため、**合意に流れやすい**
- `knowledge_sources` がほぼ同一のロール同士(例: ceo-advisor と strategy-advisor)は
  同じ資料から同じ主張が出るため、構造的に対立が生まれにくい
- SKILL.md の制約(主張への根拠ファイル引用の必須化、「拾えていない視点」欄)を必ず使うこと

## レベル1.5: 別セッションで個別に実行し、人間が持ち寄る

各ロールをそれぞれのサーフェス(別Projectなど)で**独立に**実行し、結果を人間が並べて
比較する方法です。追加インフラは不要で、互いの出力に引きずられないため
視点の独立性は本物です。

**向いている場面**: 重要な判断の前に、独立した複数の見立てが欲しい時
(疑似会議の「合意に流れやすい」性質を避けたいが、Issue管理までは要らない場合)

## レベル2: GitHub Issues連携(本当に非同期で動かす必要がある時だけ)

依頼をIssue化し、ラベルで担当ロールと依存関係を管理する方法です。

```bash
gh issue create --title "SNS投稿案の作成" --label "todo,role/sns-management"
gh issue create --title "先月の広告効果分析" --label "todo,role/marketing-analysis"
gh issue create --title "両方を踏まえた来月の予算配分決定" --label "blocked" \
  --body "Depends on: #1, #2"
```

`./scripts/check-blocked.sh` を定期実行すると、依存Issueがすべてcloseされたタスクの
`blocked` ラベルが `todo` に付け替えられ、統合タスクが自動的に着手可能になります
(fan-inパターン)。

**導入するかどうかの判断基準** — 以下が**両方**当てはまる場合のみ。それ以外は
レベル1/1.5で十分です。

1. 複数の業務が本当に別々のペース・タイミングで進む(片方が数日かかる、など)
2. 「誰が・いつ・何を依頼し、いつ完了したか」を後から追跡する必要がある

**中途半端な移行をしない**: 格上げは**業務ライン単位**で行ってください。
「この業務の依頼はすべてIssueで受ける」と決めた業務だけをGitHub化し、同じ業務の依頼が
Issueとチャットに分散する状態を作らないこと。それ以外の業務はレベル1/1.5に留めます。

**機密情報の扱いに注意**: Issue本文には機密の実データを書かず、「参照ID」だけを書いて
実データは安全な場所から取得する設計にしてください
(`knowledge/README.md` の機密度ルール参照)。
