# meeting-simulation — 疑似会議シミュレーター

## 使用タイミング
複数のロール(業務単位でも人格単位でもよい)の視点を比較・統合したい時に呼び出す。
例:「経理視点と経営企画視点で、この投資判断について議論して」

## 事前チェック(自問自答に陥らないために)

参加ロールの `knowledge_sources` がほぼ同一の場合(例: ceo-advisor と strategy-advisor)、
同じ資料から同じ主張が出て議論が形式的になりやすい。その場合は開始前にユーザーへ
「参加ロールの視点が近いため、参照ナレッジの異なるロールの追加、または
`governance/coordination.md` レベル1.5(別セッションでの独立実行)を検討してください」
と伝えた上で、続行するか確認する。

## 実行方法

1. ユーザーから、議論させたい2〜4個のロール(roles/配下のROLE.md)と、論点を受け取る
2. 各ロールの `knowledge_sources` と `前提・ルール` を読み込む
3. 各ロールの視点になりきって、それぞれの立場からの主張を1〜2ラウンド出す
   - **各主張には根拠となるナレッジファイル名を必ず添える**。ファイル根拠のない主張は
     「(一般知識による補足)」と明示する
   - 各視点は自分の `knowledge_sources` の範囲内でのみ主張する
   - 他の視点の意見に対して、賛成/反対/条件付き賛成のいずれかで反応する
4. 論点が出尽くしたら、以下の形式でまとめる

## 出力フォーマット

```
## 論点: [議題]

### [ロールA]の主張
- (主張)(根拠: knowledge/xxx/yyy.md)

### [ロールB]の主張
- (主張)(根拠: knowledge/xxx/zzz.md)

### 対立点
- (どこで意見が割れているか)

### 一致点
- (どこは合意できているか)

### この会議で拾えていない視点
- (参加していないロールの視点、不足している情報、聞くべき現場の声)

### 論点整理(結論ではなく判断材料)
- (最終判断に必要な材料を整理。断定はしない)
```

## 制約事項

- 参加ロールのうち、いずれかが `type: advisory` かつ `escalation_required: true`
  の場合、疑似会議の結論も同様にエスカレーション対象として扱う
  (「これは判断材料であり、最終判断は人間が行ってください」を必ず付す)
- 各視点は自分の `knowledge_sources` 外の情報を勝手に使わない
  (経理視点が戦略データを勝手に参照する、といったことをしない)
- **対立点が1つも出なかった場合、それを「全会一致」として報告しない**。
  「視点が実質的に同一である可能性が高い(参照ナレッジや前提が同じ)」ことを
  警告として明記する
- 議論が3ラウンドを超えても収束しない場合、それ自体を「意見が分かれている論点」として
  正直に報告する(無理に結論を作らない)

## 向いていないケース
- 独立した複数の見立てが欲しい(合意に流れるのを避けたい)
  → `governance/coordination.md` のレベル1.5(別セッションで独立実行)
- 本当に長時間・非同期で並行作業させたい
  → レベル2(GitHub Issues連携)
