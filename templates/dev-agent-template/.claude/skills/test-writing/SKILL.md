# test-writing

## 使用タイミング
builderが実装と合わせてテストを書く時に参照する。

## 基準

- 新規実装には最低限「正常系1件・異常系1件・境界値1件」のテストを書く
- テスト名は「何をテストしているか」が読んだだけで分かる形にする
  (例: `test_returns_404_when_user_not_found`)
- モック/スタブは最小限にする。実際の挙動に近い統合テストを優先する

## 自動リトライループ(binary eval方式)

builderは以下のループを自走する:

1. テストを実行する
2. 失敗があれば、失敗理由を分析し実装を修正する
3. 再度テストを実行する
4. 全て通るまで繰り返す(最大5回。テスト・ビルド・lintの失敗対応を合算してカウントする)
5. 5回を超えても通らない場合は `AGENTS.md` のエスカレーション条件に従い、
   Issueに `needs-human` ラベルを付けて人間に報告する

## 完了報告フォーマット

```
## テスト結果
- 実行件数: N件 / 成功: N件 / 失敗: 0件
- 追加したテストファイル: path/to/test
- リトライ回数: N回
```
