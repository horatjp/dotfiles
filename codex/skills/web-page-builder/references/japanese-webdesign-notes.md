# 取り込みメモ: ronantakizawa/japanese-webdesign

- 出典: https://github.com/ronantakizawa/japanese-webdesign （SKILL.md 386行 + reference/ 2ファイル）
- 目的: 日本のユーザー向けWebデザイン最適化（文化的UX原則・情報密度・信頼シグナル・ローカライズ）

## 良い点・転用ポイント

1. **文化原則を設計判断に接続**:
   - 安心（Anshin）: 全情報を先に見せる。隠すと疑われる。「全部見せていないなら何を隠している？」という消費者心理
   - 一目瞭然: クリックなしで必要情報がすべて見える
   - 欧米の「Less is more」に対し日本は「More is trust」。漢字は音読せず意味が取れるため高密度レイアウトを速くスキャンできる
2. **弁当箱レイアウト**: 12カラムgrid + dense flow のモジュラーブロック。9ブロック以下に抑える
3. **信頼シグナルの具体リスト**: スタッフ写真、認証マーク、創業年数、満足度%、会社情報（住所・電話・代表者名）、「当日出荷」「送料無料」バッジ
4. **フォームは全項目を先に見せる**（ウィザードで隠さない）+ 確認文化（注文内容確認→確認ダイアログ→最終確認→完了）
5. **日本語タイポグラフィの実務値**:
   - フォントスタック: Hiragino Kaku Gothic ProN → Yu Gothic Medium → Meiryo → Noto Sans JP
   - 行高185-200%、1行約35文字、イタリック禁止（描画が崩れる）、太字は控えめに（色・サイズで階層化）
   - 明朝=Serif（フォーマル）、ゴシック=Sans-Serif
6. **大文字が存在しない言語での階層表現**: サイズ差・色背景・枠線・アイコン/バッジ・太字で作る
7. **色の慣習**: EC=赤/オレンジ（楽天型）、比較サイト=青（価格.com型）、ポータル=マルチカラー（Yahoo型）、季節色（桜ピンク・紅葉）
8. **ナビゲーション**: ハンバーガー回避、メガナビ+件数表示、モバイルはタブバー
9. **frontmatterに globs**（`**/*.html` 等）を持たせ、対象ファイル種別を明示するパターン
10. 詳細は reference/component-patterns.md（実装例）と reference/cultural-context.md（文化背景）に分割

## 後半（EC・B2B・モバイル・文化）の要点

- **商品ページ**: 画像10-20枚（3-5枚ではない）、仕様表を網羅、返品ポリシー全文掲載（リンクだけにしない）、ランキング表示
- **価格表示**: 希望小売価格+セール価格+割引額と%+**税込/税抜**+獲得ポイント
- **決済**: クレカのみは購入者の最大30%を失う。コンビニ決済・PayPay・LINE Pay・楽天ペイ・銀行振込・代引を併記
- **B2B**: CTAフローは「資料ダウンロード → 無料トライアル → お問い合わせ」。敬語必須、セキュリティ認証（ISO 27001等）、サポート時間明記
- **モバイル**: 密度を維持（2-3列グリッド、単一列にしない）、タブバー固定、12pxも許容
- **文化的注意**: 忌み数4（死）・9（苦）を目立たせない、名前を赤字にしない（葬儀連想）、エラーメッセージは謝罪調（「お手数ですが、再度ご確認ください」）
- **A/Bテストの実証**: 楽天=クラッター版が高CV、Yahoo Japan=モダン化でユーザー苦情→差し戻し、Amazon Japan=情報追加で売上増
- **チェックリスト**を末尾に持つ（クリック不要で全情報可視/信頼シグナル/確認ステップ/税込表示/イタリック不使用 等18項目）

## 教訓

- 日本語サイト作成時のデフォルト値（行高・letter-spacing・フォントスタック・イタリック禁止）はスキル本文に必ず入れる価値がある
- ターゲット文化によって「良いデザイン」の定義が反転する（密度・情報量）ことを分岐条件として持つ
