# 日本語サイトのデフォルト（japanese-web）

日本語のWEBサイトを作るとき、Step 1のDESIGN.mdに必ず反映するデフォルト値と判断基準。

## フォントスタック

和文と欧文を分けて考える。日本語フォントは7,000〜16,000グリフあり、Webフォントは読み込みコストに注意。

```css
/* 和文（ゴシック = Sans-Serif） */
font-family: "Noto Sans JP", "Hiragino Kaku Gothic ProN", "Hiragino Sans",
             "Yu Gothic Medium", "Meiryo", sans-serif;

/* 和文（明朝 = Serif。フォーマル・エディトリアル向け） */
font-family: "Noto Serif JP", "Hiragino Mincho ProN", "Yu Mincho", serif;

/* 欧文（英数字を混植で立てたい場合、和文の前に置く） */
font-family: "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI",
             "Noto Sans JP", ... , sans-serif;
```

## タイポグラフィの数値

| 項目 | 推奨値 | 備考 |
|---|---|---|
| 本文行高 | 1.7〜2.0 | 欧文の1.4〜1.5より広く取る |
| 本文letter-spacing | 0.04em〜0.1em | 見出しは0か僅かに負でよい |
| 1行の文字数 | 約35文字 | 読みやすさの目安 |
| フォントサイズ | 欧文同等物より10-15%小さめでも可読 | 本文16px基準は維持 |
| イタリック | **使わない** | 日本語で描画が崩れる |
| 太字 | 控えめに | 階層はサイズ・色・背景で作る |

## 禁則処理・レンダリング

```css
body {
  word-break: normal;
  overflow-wrap: break-word;
  line-break: strict;                       /* JIS禁則を厳格に */
  font-feature-settings: "palt" 1, "kern" 1; /* 約物のプロポーショナル詰め+カーニング */
  -webkit-font-smoothing: antialiased;
  text-rendering: optimizeLegibility;
}
```

- 行末禁則（行末に来てはいけない）: `（「『【`

## 階層表現（大文字が存在しない言語）

日本語には大文字/小文字がないため、階層は次で作る: サイズ差、色付き背景ボックス、枠線・罫線による明確な区切り、アイコン・バッジ、（控えめな）太字。英語のALL CAPSアイブロウに相当するものは、小さめのゴシック+letter-spacing広めで代替する。

## 文化的UX（オーディエンスが日本の一般消費者の場合)

欧米の「Less is more」に対し、日本のECや比較サイトでは「More is trust」が機能する。漢字は視認で意味が取れるため高密度でも速くスキャンできる。ただしSaaSやブランドサイトではミニマルも一般的 — **Step 0のオーディエンス判断で密度を決める**。

- **安心（Anshin）**: 情報を隠さず先に全部見せる。隠すと「何を隠している？」と疑われる
- **一目瞭然**: クリックさせずに必要情報を見せる。「詳細を見る」ボタンの奥に本質情報を隠さない
- **信頼シグナル**: 会社情報（住所・電話・代表者名）、創業年数、認証マーク、顧客満足度、レビュー件数、「送料無料」「当日出荷」等のバッジ
- **フォーム**: 全項目を先に見せる（ウィザードで隠さない）+ 進捗表示。確認画面文化（入力→確認→完了）
- **ナビゲーション**: ハンバーガーより全項目露出（メガナビ・モバイルはタブバー）が好まれる（EC・ポータル系）
- **色の慣習**: EC=赤/オレンジCTA（楽天型）、比較・情報=青基調（価格.com型）、ポータル=セクション色分け（Yahoo型）、季節色（桜・紅葉）の活用
- **弁当箱レイアウト**: 12カラムgrid+denseフローのモジュラーブロック。9ブロック以下に抑える

## サービスカテゴリ別プリセット（Step 1の初期値）

| カテゴリ | 書体 | 行高/字間 | その他 |
|---|---|---|---|
| Consumer App（LINE/メルカリ型） | Noto Sans JP | 1.7 / 0.04em | モバイルファースト375px、タップ48px以上 |
| B2B SaaS（SmartHR/freee型） | Hiragino優先 | 1.8 / 0.04em（表は1.5可） | 中立パレット+明確なアクション色、高情報密度 |
| Editorial/Media（note/Qiita型） | 本文は明朝系 | 1.9-2.0 / 0.06em | 1行38-42文字、UIはゴシック |
| Retail/Lifestyle（MUJI型） | プレミアムはセリフ | 2.0 / 0.08em | 無彩色系、写真が主役 |

## その他の文化的注意

- **忌み数**: 4（死）・9（苦）を価格・番号で目立たせない。名前を赤字にしない（葬儀連想）
- **エラーメッセージは謝罪調**:「メールアドレスの形式が正しくありません。お手数ですが、再度ご確認ください。」
- **B2Bは敬語**: CTAフローは「資料ダウンロード → 無料トライアル → お問い合わせ」が定番
- **EC価格表示**: 税込/税抜を必ず明記、割引は額と%の両方、獲得ポイント表示
- **モバイルでも密度を維持**: 2-3列グリッド（単一列に減らさない）、ナビはタブバー固定
- フォントスタックには「簡略化禁止」の注記を付ける（AIが `MS Gothic` や generic sans-serif に簡略化しがち）
