# 画像の調達と実装(手順6の必読リファレンス)

モックアップに画像を組み込む直前に読むファイル。禁止事項(実行しているAI自身が画像を描かない)と素材の優先順位の要約はSKILL.md手順6にあり、ここでは各ティアの具体的な調達手順と実装形を扱う。

## 素材の優先順位(詳細)

1. **実素材**(現状サイトの写真・ユーザー提供素材): 権利がユーザー側にあり提示しても安全で、「今ある素材でここまで変わる」という提案として最も強い。ダウンロードやアップロードで実体が手に入ればbase64埋め込み(最も確実)。実体が手に入らない場合でも、**提案フェーズに限り現状サイトの画像URLを直リンクしてよい**——サイトが公開中なら、ユーザーがブラウザで開けば表示される。直リンクはFPOブロックに重ね、本実装時にダウンロードして差し替える前提をindex.htmlに明記する。低解像度なら小さめ配置・グリッド化・duotone等の加工で逃がし、限界があれば「この方向は撮影推奨」と正直に伝える
2. **生成画像**(画像生成に対応したツール・依頼手段が環境にある場合のみ。例: 画像生成MCPツール、画像生成対応の外部エージェント): 実行AIは仕様書を書き、生成は相手に任せる。FPOに書く内容(被写体・構図・光)に案のトーン(色調・質感・時間帯)を足したものが、そのままプロンプトの骨子になる。運用ルール:
   - 同一案内の生成画像はトーン指定をプロンプトに共通で入れ、アートディレクションを統一する
   - 画像内に文字(特に日本語)を入れない。看板・ロゴなどの文字はHTML/CSS側で載せる
   - 実在の店舗・商品・人物を「本物らしく」再現しない。生成イメージである旨と差し替え前提をindex.htmlに明記する。人物のリアル生成は品質リスクが高いため、必要なら3の実写ストックを優先する
   - 生成物はPILで圧縮してbase64埋め込み(実ファイルの扱いは1と同じ)
   - 生成に失敗した・品質が低い場合は無理に使わず、3または4に落とす
3. **ライセンスが明確なフリー素材**(Unsplash等): 取得できる環境ではダウンロードしてbase64埋め込み。取得できない環境では、次の検証済み手順で画像URLを特定し、モックアップ限定で直リンクする:
   - `web_search`(相当の検索ツール)で「unsplash <被写体の英語キーワード>」を検索し、結果に出る`unsplash.com/s/photos/...`ページを`web_fetch`(相当のURL取得ツール)で読む(日本語キーワードより英語の方が精度が高い)
   - 取得したテキストに`images.unsplash.com/photo-...`形式の画像URL・alt文(写真の説明)・撮影者名が含まれる。**alt文を読んで被写体が合うものを選ぶ**。`plus.unsplash.com`や「For Unsplash+」表記の有料素材は必ず除外する
   - URL内の`w=`と`q=`パラメータは`w=1600&q=75`程度に調整して使う
   - 直リンクの`img`はFPOスタイルのブロックに重ね、読み込めない環境ではラベル付きプレースホルダーが見える構造にする。「イメージ写真・差し替え前提」であることと撮影者名をindex.htmlに明記する
4. **写真プレースホルダー(FPO)**: 1〜3を尽くしても素材がない箇所の最後の手段。画像をでっち上げるのではなく「指定」する——実装時と同じ比率の色面ブロックに「ここに: 店舗外観/横位置/夕方の光」のように被写体・構図・撮影メモをラベル表示する。これがそのまま撮影リストになり、index.htmlの「必要な素材」欄に要約を載せる。写真が主役級の業種(飲食・美容・宿・小売など)でFPOだらけの案は説得力が大きく落ちるため、その前に1〜3の確保を尽くすこと

## 直リンク画像の実装形(必須)

直リンク(上記1・3)は次の形で組む。

```html
<figure class="photo-frame" style="aspect-ratio: 4/3;">
  <span class="fpo-label">ここに: 被写体・構図・光のメモ</span>
  <img src="(fetch結果からコピーしたURL)" alt="◯◯(イメージ写真・差し替え前提)"
       loading="lazy" onerror="this.style.display='none'">
</figure>
```
```css
.photo-frame{position:relative; overflow:hidden; background:#eee}
.photo-frame .fpo-label{position:absolute; inset:0; display:flex; align-items:center;
  justify-content:center; text-align:center; font-size:11px; padding:12px}
.photo-frame img{position:absolute; inset:0; width:100%; height:100%; object-fit:cover}
```

- **フレーム側に`aspect-ratio`または`height`を必ず与える**。中身がすべて`position:absolute`のため、無指定だと高さ0に潰れ、画像が0x0で見えなくなる。flexコンテナ直下に置く場合は幅も指定する
- **失敗をサイレントにしない**: 表示環境が外部画像をブロックすると`onerror`で画像が消え、FPOラベルだけが残る——ユーザーには「壊れている」ように見える。ページ末尾に読み込み失敗の検知バナーを必ず入れ、理由と対処を画面内で伝える:

```html
<script>
addEventListener('load',()=>{setTimeout(()=>{const b=[...document.images].filter(i=>i.src.startsWith('http')&&(!i.complete||i.naturalWidth===0));if(b.length){const d=document.createElement('div');d.textContent='※ 外部画像 '+b.length+' 枚がこの表示環境で読み込めていません。ファイルをダウンロードしてブラウザで開くと表示されます。';d.style.cssText='position:fixed;left:12px;right:12px;bottom:calc(12px + env(safe-area-inset-bottom));z-index:999;background:#1f2328;color:#fff;padding:10px 16px;border-radius:8px;font-size:12.5px;opacity:.95;text-align:center';document.body.appendChild(d)}},600)});
</script>
```

寸法指定と検知バナーの有無は`scripts/lint_mockup.py`が機械検査する(手順7)。

## claude.aiのプレビューで画像まで見せたい場合

プレビューは外部画像をブロックするため、直リンクはFPOラベル+検知バナー表示に落ちる(環境のセキュリティ仕様であり、HTML側から解除はできない)。プレビュー内で写真まで見せる必要があるときは、base64埋め込みに引き上げる:

0. まず疎通確認: `curl -sI`で画像ドメインに200が返る環境(ネットワーク許可リスト設定済み)なら、以下の往復は不要——そのままダウンロード→base64で完結できる

1. fetchで集めた候補を「番号+被写体(alt文)+撮影者+URL」のリストでユーザーに提示し、使うものを保存してアップロードしてもらう(実素材が存在するならそちらを最優先で依頼する)
2. アップロードされた画像はPILで圧縮(用途に応じて長辺800〜1600px・品質70前後)し、base64で埋め込む——外部リクエストが発生しないため、どの表示環境でも確実に表示される
3. ファイル肥大に注意: base64は1枚あたり50〜150KB程度HTMLを太らせる。合計1MBを超えそうなら、ヒーロー等の主要写真だけ埋め込み、残りは直リンク+検知バナーのハイブリッドにする

画像をダウンロードできる環境(Claude Code、Codex CLI、Cowork等のローカル実行)ではこの往復は不要で、最初から全量をbase64にできる。プレビュー完結が必須の案件は、そちらの環境で回すのが最も速い。

## 枚数と配分

写真が主役級の業種(飲食・食品・美容・宿・小売など)では、トップページ相当のモックアップで5〜8枚を目安にする——ヒーロー/主力商品・サービス/一覧グリッドの各項目/人・店内・仕事風景/店舗案内のうち、その骨格に存在するセクションをカバーする。2〜3枚では「写真を使った案」としての説得力が出ない。タイポグラフィ主導などで意図的に写真を絞る案は作ってよいが、その場合は仮説の戦略1行にその旨を含め、調達の手抜きと区別する。

調達は効率よく行う: Unsplashの検索ページは1回のfetchで多数の画像URLが取れるので、先に必要な枚数と用途(ヒーロー用・商品用など)をリスト化してから一括で確保・配分する(1枚ごとに検索し直さない)。生成画像を使う場合も同じで、必要リストを作ってからまとめて生成を依頼する(1枚ずつ依頼しない)。同一ページ内の写真はトーンを揃えるため、なるべく同じ撮影者・同じシリーズから選ぶとよい。

画像検索で見つけた画像のうち、権利が不明なドメインのものはチャット内での雰囲気のすり合わせ(参考提示)に留め、モックアップには埋め込まない。実在の競合企業や特定の個人が写る画像は参考提示でも避ける。

## 埋め込み方の原則

base64埋め込みが基本(実素材・生成画像はPILで圧縮——長辺1200〜1600px・JPEG品質75前後——してから埋め込み、単一ファイルを保つ)。外部URLの直リンクを許すのは、提案フェーズの現状サイト画像(上記1)とライセンス明確なストック画像(上記3)の2つだけで、いずれもFPOブロックに重ねる。

埋め込みの前に、サンドボックスから対象ドメインへの疎通を実測する: `curl -sI "<画像URL>"` が200なら、ダウンロード→圧縮→base64が全自動で通る(claude.aiでも、ネットワーク許可リストに画像ドメインが含まれていれば可能)。`403` + `x-deny-reason: host_not_allowed` なら許可リスト外なので、直リンク+検知バナーまたはアップロード経由にフォールバックし、あわせて「設定 > 機能 > Code execution and file creation > Allow network egress のドメイン許可に `images.unsplash.com` 等を追加すれば全自動化できる(反映には新しい会話が必要な場合がある)」と一度だけ案内する。

写真に文字を重ねる場合はスクリム(半透明オーバーレイ)を必須とし、コントラストはスクリム適用後の実効的な背景色で`scripts/check_contrast.py`にかける。
